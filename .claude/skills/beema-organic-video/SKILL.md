# Beema organic video skill

Engine: `shorts/engine/` (CLI `beema.py`, library, compliance gate, registry, Slack delivery). Renderer: Remotion project `shorts/pde5-explainer` (composition `Clip9x16`, three.js scenes). Read `shorts/engine/README.md` for setup, costs and limits. Run everything with `shorts/pde5-explainer/.venv/bin/python shorts/engine/beema.py ...` (call it `PY`).

## Hard rules (do not relax)
- **Never publish.** Delivery to Slack is not authorization to post. Posting stays manual until Matt explicitly approves an automated workflow. Never run `beema.py daily` or `deliver` unless Matt asks: it renders AND posts to Slack (a tirzepatide video once appeared in Slack from an earlier session's daily run). Never post to Slack yourself.
- **Never stage or commit** unless Matt says so in that message (repo rule). Never start, stop or restart the dev server.
- **Do not render the full video until Matt OKs the script.** Compose with `--preview --stills` first and show the script, the compliance findings and stills.
- Compliance statuses are `BLOCKED`, `NEEDS_HUMAN_REVIEW`, `AUTO_CHECKS_PASSED`. None means approved. A person signs off (`registry signoff`).
- Never describe compounded products (ED Mints, tirzepatide, semaglutide, BPC-157) as FDA-approved, generic, "same as", or clinically proven. Always "Beema Health", never bare "Beema". No em dashes anywhere (code, copy, tests).
- No testimonials, patient stories, before/after, invented packaging, or outcome/speed/performance claims. No "heals/repairs/treats", no dosing, no "research shows" without a cited human source. Say what is unknown. Mechanism wording is "acts on", "plays a part in", "is built to", never a promise of a result.
- Never transfer tablet onset/duration to ED Mints (the 30 to 60 minute figure is unverified; the live page says "about 30 minutes, provider confirms").
- Tablet bottle photos show "Generic Cialis/Viagra" on the label, so they are OFF by default (`config.use_labeled_photos=false`). A product photo whose label makes a claim (the tirzepatide vial says "Weight loss Medication") is a review item.
- **Prices:** use only a price Matt has given, stored in `products.json` with its source. If the repo disagrees (for example `src/lib/medication-pricing.ts` said $597/3 months = $199/mo while Matt said $197/mo) use Matt's number, record the conflict in `products.json` and `claims.json`, and tell him. Never add savings, "cheaper" or comparison language.
- If anything is uncertain, flag it for human review. Do not guess.

## Workflow for a new video
1. **Orient:** read this file, the README, `products.json`, `claims.json`, and the product's `library_src/<product>.py` (so the new hook is genuinely new: a duplicate hook happened once). Check the repo's own pages for what Beema says (`docs/features/treatment-pages.md`, `src/lib/*-page.ts`) and the legitscript / meta-ads compliance skills.
2. **Research** any claim you will make: primary source if possible; record the source and an honest `status` in `claims.json`. Statuses that count as verified: `verified`, `verified_by_matt`, `verified_basic_pharmacology`, `general_education`. Anything else forces a review item (that is the point).
3. **Write the script** in `library_src/<product>.py` (new hook, meat, CTA; keep existing IDs). See "Script and animation design". Then `PY engine/beema.py library build` and `library lint`.
4. **Compose a preview:** `PY engine/beema.py compose --product P --hook ID --meat ID --cta ID --preview [--stills 1,5,9]`. (The "NN.Ns" printed after the preview path is RENDER time, not video length.) Output: `out/<id>/{package.json,captions.md,compliance.json,voice.wav,preview.mp4,stills/}`.
5. **Prove the voice:** `PY engine/tools/check_voice.py engine/out/<id>/package.json` and compare SAID with HEARD for every drug name, number and URL (see "Voice").
6. **Look at stills at the CUE moments**, not at arbitrary times: get the spoken times from `package.json -> words`, then render stills just before, at, and after each animation step (small Python call: `render.stills(pkg, [t1, t2, ...])`). Check legibility over the backdrop, nothing clipped at any canvas edge, labels in sync, disclosures present, text size consistent. Fix, recompose, look again. Look at mid-transition frames too.
7. **Show Matt:** script (time-stamped), compliance findings, stills, voice check results, and a short list of decisions only he can make. Then wait.
8. After his OK: full render (`compose` without `--preview`), captions, `registry signoff`, and manual delivery only if he asks.
9. **Track:** `beema.py registry import-metrics FILE.csv`; `registry recommend` gives hypotheses, not conclusions.

Also: `tests` (`PY -m pytest engine/tests -q`) must pass; add tests for anything new. `cd shorts/pde5-explainer && npx tsc --noEmit` after any TSX change.

## Script and animation design
- **Write for the ear.** Contractions, a lead-in now and then ("So,", "Here's the thing,"), two short ideas joined by a comma instead of a full stop, varied length. Read each line aloud; if you would not say it to a friend, rewrite it. Avoid "Introducing", "Are you tired of", "Say goodbye to". The engine merges neighbouring short sentences into one synthesis call and keeps pauses tight; do not fight it with one-word sentences. Open with a question, a surprising fact or a relatable problem. One idea per video. About 40 to 65 seconds.
- **Animate what is being said, on the word it is said.** Use the `story3d` visual. `cues` is a list of words from the script in spoken order (a repeated word resolves to the next occurrence); `stages` is the label shown while each step is on screen (`{"t": "Human stomach", "cue": "stomach"}`); `texts` lists any text drawn inside the 3D scene (so the gate lints it); `hold_s` adds silence after the beat so the last animation can finish. Callouts, versus cards and labels can fire on a word too (`{"t": "Lab studies", "at": "lab"}`, `cue2`). Write the script in the SAME ORDER as the animation (stomach, then fluid, then protein, then zoom, then the piece), not the order a sentence would naturally put clauses. Never show something the narration has not reached; never leave a spoken phrase without a matching visual. Two cue words close together (0.5 s) make a cramped animation; space them or merge the steps.
- **Be creative: show a METAPHOR, not just the literal nouns.** For every sentence ask "what is the most vivid, concrete picture of this idea?" and build that. Working examples (all in `scenes3d.tsx`, modes `gutmsg`, `receptors`, `appetite`, `compound`, `fda`, `provider`, `nocharge`, plus the semaglutide set: `balance` willpower versus biology weights on a balance that levels, never tips to biology; `radio` meal, tower broadcasting a fullness wave, brain tuning a radio, grey static bars; `glp1key` GLP-1 orb and other signals drifting past, one key slides to one lock and the shackle opens; `centers` receptor cup sends dots to a brain whose appetite-center spots light in turn; `belt` stomach drains onto a conveyor whose speed eases down, with a speed bar). `fda` takes `"card": "Compounded <drug>"` in the visual so the stamped card names the right product; scenes also receive the whole visual as `v`: gut sends chat-bubble alerts to a brain that lights up; one double-ended golden key fits two locks (two receptors); appetite dial plus stomach emptying clock; flask pours into a vial with a "Made for one patient" tag under a Licensed pharmacy sign; a generic columned building, a gavel slams a red NOT FDA-APPROVED stamp onto the product card (shake, shockwave, sparks); provider figure, ticking clipboard and magnifier; Rx pad crossed out and a $0 coin spinning in. Molecule-style modes in `story3d.tsx`: `build` (loose beads link into a helix chain and count up) and `origin` (stomach, fluid, protein, zoom, long chain, one piece highlighted). Each new idea gets its own mode, with a cue per spoken step.
- **Metaphor safety.** Illustrations never imply a result, an endorsement, or an agency action. The building is generic (no seal, logo or real insignia). "Illustration" (or "Illustration, not the actual structure" for molecules) is shown on screen. Anything showing a government agency, a body, a needle, or a patient outcome goes on the review list.
- **Look and motion.** Brand honey `#EEB318`, ink `#121419`, Outfit/Figtree, honeycomb motif, real product photos only. Backdrop is a real three.js honeycomb, steady (one pose per scene, very slow drift) and DIMMED under `story3d` so the foreground is the focus. NO fast or jerky camera moves; the only camera motion that matters is a slow zoom in the foreground tied to a spoken word. Scene changes are a short fade, never a wipe or mask (those clipped text). Kinetic text is ONE size on every beat. Products sway in CSS 3D over a hex platform; cards and labels rotate in with depth. Short beats (one clause, 2 to 4 s) give the cuts; there are no jump cuts, flashes or punch-ins.
- **Labels.** Every beat has a short `screen` label (2 to 4 words) or `stages`; `callouts` (2 or 3 chips) where useful. Labels are linted like voiceover.
- **3D rendering pitfalls (all hit once).** `ThreeCanvas` needs INTEGER width/height. Keep every 3D object inside its canvas (a translucent shell fills the frame when zoomed: fade it out first; check top and bottom edges). Plain `Txt` planes need fonts loaded (`useFontReady`). Do not use `ɝ`-style tricks in visuals either: verify by looking. Coordinates matter: a gavel "hitting" a stamp must be positioned from the stamp's own position.
- **Visual types for beats:** `story3d` (modes above), `kinetic`, `chain3d`, `product`, `versus` (myth/fact or labels, `cue2`), `checklist`, `steps`, `warn`, `diagram`, `price`. Fields: `screen`, `callouts`, `bg` (`ink`/`honey`/`cream`), `hold_s`, `note`. The hook shows the product photo in 3D (or `hook_hero: "chain"` for educational mode). The CTA can carry `price={label, amount, per, fine}` for an animated price badge that counts up on the spoken amount.

## "3D" means a world you move through (user rule, 2026-11-18)
A flat object that sits still, or a picture on a plane, is NOT 3D, even if it is rendered by three.js (an orange that does not turn, or show its depth, reads as 2D). Every video must be 3D you can feel:
- **One continuous world, one moving camera.** Use the `world3d` visual (`world3d.tsx`, `WorldV`): all adjacent `world3d` segments merge into ONE scene and the camera flies on the spoken words (orbit around the objects, dolly in, drop low, rise above), with real parallax between near and far objects. The camera should be moving or drifting in every second of the video; objects never sit dead still.
- **Solid objects with depth.** Stacked boxes, glass cylinders, spinning bead chains, capsules, spiked spheres, tori, a syringe, a vial. Things rotate so their dimensions show, cast light, and overlap in depth. No flat cards; text chips are billboards that always face the camera and are secondary.
- **Every object appears, changes or moves on the word that names it** (cue by exact spoken word, `bpc-157#2` = second occurrence), and leaves when the narration moves on. Reuse the pattern: a keyframe list of camera poses keyed to cues, state derived from `tg` (global time), nothing timed by guesswork.
- **Metaphor first.** The article's idea becomes a physical scene (e.g. glass pillars whose filled height is the amount of human safety data), not a slideshow of nouns.
- **Check it in stills before the long render.** `render.stills(pkg, times)` at a cue time for each beat; look for cropped objects (portrait frame: use fov about 52 and pull the camera back), empty first frames (start rising at t=0.15, not at the first cue), sunk objects poking through the floor, and signs facing away from the camera (face the camera with `atan2(cam.x, cam.z)`).
- **Worked example:** `PeptideWorld` in `shorts/pde5-explainer/src/engine/world3d.tsx`, built by hand for the peptide side-effects article (build script pattern: compose.build_package with parts, `visual: {"type": "world3d"}` on the hook and every beat, add `hold_s` on the last beat so the final object has screen time).
- **Peptide videos are education only:** the gate BLOCKS the words Beema, link, prescribe, provider, patient, plan, price and any call to act, in narration and captions. The end card still carries the logo.

## Voice and pronunciation (the engine cannot hear: prove it)
- Kokoro gets explicit phonemes from `config.phonemes` (one quick token with the right stress); `config.pronunciation` holds plain respellings for ElevenLabs. Never use a capital-syllable respelling for Kokoro ("ZEP" is spelled out letter by letter). Never use the `ɝ` symbol (Kokoro swallows the first syllable: a recognizer heard "Sepatine"); use `ɜɹ`. A middle `ʌ` was heard as the clearest "-pa-" (schwa was heard as "-pi-").
- **semaglutide = sem-uh-GLOO-tide**, phonemes `sˌɛmʌɡlˈutˌaɪd`. The secondary-stress mark on the first syllable matters: `sɛmʌɡlˈutˌaɪd` (no mark) was once heard as "Sima Glutide". The recognizer spells it "semagluetide" (fine). Six variants were tested in a full sentence, in the not-FDA-approved line and in the URL line before choosing.
- **"Beema Health" is not provable with the recognizer:** it hears "BMA Health", "Be My Health" and "bmhealth.com" in the tirzepatide video too. Ask Matt to listen to the brand name and URL.
- **tirzepatide = ter-ZEP-uh-tide**, phonemes `tɜɹzˈɛpʌtˌaɪd`, said fast as one word. `GIP` is spelled out "G I P"; `GLP-1` is "G L P one". Semaglutide and any new drug name need phonemes tested the same way.
- URLs: the engine speaks `beemahealth.com/x` as "beema health dot com slash x" (it splits at the slash so a phoneme override is never glued to "com/"). Do not work around this in the script.
- **After EVERY compose run `PY engine/tools/check_voice.py engine/out/<id>/package.json [b2 cta ...]`.** It transcribes each segment with Whisper and prints SAID next to HEARD. A spelling difference ("Terzepatide") is fine; a dropped syllable ("Sepatine"), a glued word ("comzepatide") or a missing sentence is a bug. A recognizer is not an ear: still ask Matt to listen. To test a new pronunciation, synthesize variants in context and transcribe each.
- Voice defaults: `am_michael`, speed 1.06, tight pauses, sentences merged up to 24 words (`config.json`).

## Lessons from the semaglutide hunger-signal video (SMG-H51 / M6 / C4)
- **Length:** hook + 7 metaphor beats + CTA + disclosure is about 70 s even after trimming; the closing disclosure (about 9 s) and the `hold_s` values are fixed cost. Plan 6 beats for 65 s. Two cues 0.4 s apart (`stomach`, `empties`) make a cramped animation: reword so they are a clause apart.
- **Scene pitfalls found by looking at stills:** black text on a plane that is wider than its sphere vanishes against the dark backdrop (make the shape bigger than the text); `Math.max(0.001, k)` on a flat mesh (belt) still draws a sliver, so gate the whole group with `k > 0.02`; a label that scales down on arrival must reach 0 or it stays as a smear on the target; hangers must be 2 units or more or a stacked weight touches the beam; keep scene content below about y=2.5 or it hits the stage pill at top left; place a plate next to the shape it names, not over a moving bar chart.
- **Unlabelled-metaphor honesty:** a metaphor that implies an effect (static, "running slower", appetite spots lighting up) goes in `claims.json` with status `metaphor_needs_human_review` and a named review flag so the gate lists it for Matt.
- **The end card prints the URL, then the CTA `screen` pill.** If `screen` is the URL it appears twice (C2 does this); use a different pill such as "Plans and details".
- **Live pages say nothing about appetite mechanism** (`weight-loss-page.ts`, `glp-1-landing.ts`). The mechanism wording rests on `claims.json -> glp1_appetite` and `src/lib/learn/semaglutide-vs-tirzepatide.ts`. Tell Matt when a script goes beyond what the live pages say.
- **Product photo review items:** the semaglutide vial photo has "Weight loss Medication" on the label and a syringe with a needle and mL markings beside it. Both are review flags.

## Disclosures, claims and the gate
- Every selling video ends with "Prescription required. Prescribing is never guaranteed, and you won't be charged if you aren't prescribed" plus the compounded line ("Compounded, not FDA-approved") where it applies. The no-charge line comes from `products.json -> no_charge` and is `verified: true` only where Beema's live pages say it (ED, tirzepatide, semaglutide). It is unverified for BPC-157 (the gate raises `no_charge_unverified`). Never in paid ads (ads use the full ISI instead; peptides have no ISI so ad format raises an error on purpose).
- **Educational mode** (`educational: true` in `products.json`, used for BPC-157): no prescribing, price, provider or no-charge language; product photo off; hook shows a 3D hero; disclosures "Compounded. Not FDA-approved." and "For education only. Not medical advice."; CTA is only "Read more".
- The gate (`beema_engine/lint.py`, `compliance/rules.json`) lints the voiceover, every on-screen string (labels, callouts, stages, `texts`, price badge, end card), captions, claims and required disclosures. It caught a "What the research shows" label and a "works in people" line; fix the copy, do not weaken the rule. Peptides have extra BLOCK rules (healing, repair, efficacy/safety claims, dosing, body parts). `$0` is allowed only where the no-charge claim is verified.
- Every compounded product always gets a human sign-off review item. Peptides also get "confirm compounding eligibility with counsel (LegitScript Standard 2) and platform policy". Review items are decisions for Matt, not noise: list them plainly.
- Captions: IG/FB/Threads under 500 characters with hashtags, X under 280 (URL = 23), TikTok, YouTube; edit the library `caption_bodies`, not the generated text.
- Claims registry (`claims.json`): every claim a script relies on, with source and honest status. Add one for any new factual sentence, and one for any price.

## Tooling notes
- `compose --version N` writes a new `out/` folder; `--force` overwrites one. Delete stale versions you made.
- `render.stills(pkg, [t1, t2, ...])` is about 3 s a still. Call it once with all the times in a single Python process; looping over background subshells silently produced nothing, and `xargs -I` with long commands fails on macOS. There is no PIL, ImageMagick or ffmpeg here, so read the PNGs one by one.
- Whole-beat cue times: load `package.json -> words`, filter by `seg`, and match each cue like `cueTimes` in `ui.ts` (lowercase, strip punctuation, substring, next occurrence).
- ESLint on `shorts/pde5-explainer/src/engine/*.tsx` reports hundreds of prettier errors on untouched files too (the engine is not prettier-formatted); only the non-prettier rules matter (no `any`).

## Nightly job (automatic 15-45 s videos at 04:00): EVERY VIDEO IS NEW
`beema.py nightly` finds highly searched topics, then WRITES two brand-new videos and delivers them to Slack as drafts. It never publishes. Details in `shorts/engine/README.md` ("Nightly job").

**The two mistakes this section exists to prevent (Matt has said this many times; it must never happen again):**
1. (2026-11-16) The nightly job assembled existing hook + meat + CTA from `library_src/`. WRONG. It must never reuse library scripts, and its animation must act out what is being said, on the word it is said.
2. (2026-11-17) The rewritten job produced videos that all LOOKED the same: same dark honey palette, same hexagon-and-logo hook, same voice, same "How does X work?" hook, same caption panel, the brand present from the first frame, and a writer that had been shown past scripts, an example beat and a "reference quality" frame, so it imitated them. WRONG. **Matt wants completely new, creative videos with different hooks, voices, looks and structures so we can A/B test. Mostly education; some may state our price (from the repo). The brand appears ONLY at the very end.**

**Hard rules for the nightly writer (enforced in code and tested in `tests/test_nightly.py`; do not weaken):**
- **The writer is BLIND.** `generate.build_prompt` gives it only: product facts, the verified claims, a shortlist of real search questions already filtered by code against the topic log (`topic_log.unused_phrases`), the stage catalog, and a random creative brief. NEVER add to the prompt: existing scripts, library text, the topic log, past hooks, "stories already told", example beats, or "reference quality" descriptions of a finished video. A test fails if any of these appear. Uniqueness is checked by validators AFTER writing, and rejections are reported WITHOUT quoting or naming the existing video (`generate._blind`).
- **Every video gets its own brief, drawn by code (`beema_engine/styles.py`), never repeating the last videos' choices (stored under `style` in the topic log):** voice (11 Kokoro voices, speed 1.0-1.1), palette (8 accent colours on dark tones, applied to backdrop, captions, actors and chips), caption style (panel or bare outlined words), hook style (12 kinds), structure (8: one extended analogy, myth-twist-truth, follow the journey, domino chain, side by side, countdown, zoom in, mini mystery), visual world (20 metaphor settings: airport, kitchen, space station...), 3D backdrop per beat (honeycomb, tunnel, orbits, grid, bubbles), and education vs price. The brief is deterministic per (date, slot, product) so a retry keeps its look.
- **The brand honey palette, the logo and the product hero appear ONLY on the end card.** The hook is its own picture (`hook_visual`: one big actor on screen from the first frame, one action on a hook word), never the hexagon + logo card. "Beema" / "Beema Health" may be spoken only in the closing line (validator rejects it earlier).
- **Price videos (about 1 in 3, never two in a row, never peptides, never semaglutide):** the closing line states the price exactly as in the repo (`products.json` prices: tirzepatide starter pack $199/month; sildenafil and tadalafil plans from $89; ED Mints from $149; Matt's pricing sheet, `price_verified_on`), no savings/"cheaper"/comparison language, plus the animated price badge on the end card and a `price_dependent` review flag. Education videos contain no `$` anywhere. Never type a price from memory: take it from `styles.price_for`. If `src/lib/simple-treatment-pricing.ts` and `products.json` disagree, tell Matt.
- **No "Illustration" label (or any disclosure caption) is drawn on nightly videos or auto-added to the Slack caption.** It spoiled the picture; Matt adds it by hand in the post caption. Do not put it back (`stage3d` visuals carry no `note`; the stage scene renders none).
- **Heavy 3D animation locked to the words is the goal:** 6 to 14 actions per beat (`storyboard.MIN_ACTIONS`), every actor in at least two actions, something changing on nearly every phrase.
- **Topics:** two per night, from the most-searched questions about the drugs we sell. Reddit's API blocks this machine, so Reddit-style demand comes from Google autocomplete on "<drug> reddit" queries (`topics.json` `question_prefixes`), the site name stripped. A question is never made twice: the topic log removes covered questions from the shortlist before the writer sees it (overlap threshold 0.4), and the validator rejects any repeat.
- When the output starts to look alike again, fix the SOURCE of the sameness (palette, voice, hook, structure, prompt content), do not tweak individual videos. Check by viewing stills of two consecutive nights side by side before telling Matt it is done.

How it works, and what to keep true when you change it:
- **Topic:** `demand.py` (Google autocomplete per product/facet) ranks products; the writer chooses ONE of a shortlist of specific searched questions from the real completions ("does sildenafil lower blood pressure"); questions already done are removed by code before the writer sees the list. Price, dose, timing, results and comparison searches are not turned into videos (they need human-approved claims).
- **Writer:** `generate.py` calls headless `claude -p` with the product facts, the claims it may rely on, the search shortlist, the stage catalog and the creative brief (and NOTHING about existing videos). It returns JSON: topic, hook, 3 beats (text + storyboard + claims), CTA, caption. New facts go under `new_claims` and are stored in `claims_proposed.json` with status `ai_proposed_unverified`, so the gate always asks a human.
- **Animation:** the generic stage engine (`pde5-explainer/src/engine/stage3d.tsx`, visual type `stage3d`). A storyboard is `actors` (brain, stomach, gut, blood vessel, plate, orb, chain, receptor, lock, key, enzyme, pill, vial, flask, clock, dial, balance, building+stamp, clipboard, provider, coin, radio, bubble, card, shield, magnifier, arrow, meter, shape) plus `script` actions (show, hide, move, scale, glow, color, label, shake, burst, spin, fill, widen, open/close, set, count, stamp, travel, connect), each fired on a SPOKEN word. No code is written at night. Add a new actor kind in `stage3d.tsx` AND `beema_engine/storyboard.py` (CATALOG) together; they must stay in sync.
- **Narration to animation match is enforced before anything renders** (`storyboard.validate_beat`): every actor is introduced on a word it illustrates; every action fires on a word that exists in that beat; every SENTENCE has an action inside it; if the narration says brain/stomach/gut/blood vessel/meal/chain/receptor/lock/key/enzyme/pill/vial/flask/clock/dial/balance/FDA/provider/radio/checklist there must be an actor of that kind (whole words: "block" is not "lock").
- **Uniqueness is enforced** (`topic_log.check_unique`): the writer is rejected if the question overlaps a logged topic for the product, or the hook or any narration sentence overlaps the whole reviewed library or the log. Rejections go back to the writer with the exact problem. The **topic log** is `shorts/engine/topics/topic_log.json` (+ generated `topic_log.md`): every nightly video is added when built and marked delivered on send; the registry and all library hooks are seeded as "already covered" (`beema.py topics seed`, `beema.py topics log`).
- **Gate and length:** the compliance gate runs on the written script (BLOCKED goes back to the writer, never ships); the REAL synthesized duration must be 15-45 s (else the writer is asked to cut or add words). Every nightly video carries the `ai_written_script_review` flag, so it always arrives as needs-human-review.
- **Peptides** are education only, never ad-like (no link, brand, price, provider/prescribing words, offers, calls to act): the gate BLOCKs it (`peptide_ad_like`); one peptide night every 4 nights, second slot only.
- **Safe ways to look:** `beema.py nightly --dry-run --date D` (topics only), `--script-only` (writes and validates scripts with the writer, no voice, no render, no Slack, touches no state). Never run `nightly` without those flags unless Matt asks: it posts to Slack. `--date D` for a new run on a date already DONE needs that date's record set aside in `state/nightly.json`.
- **Schedule:** `bash shorts/engine/scheduler/install.sh [install|uninstall|status|run-now]` (launchd -> Terminal wrapper; plain launchd cannot read ~/Documents).
- **Exception to "do not render until Matt OKs the script":** the nightly job renders and delivers drafts by design (Matt asked for it); a person reviews each draft in Slack before anything is posted.
- After changing the stage engine, validator, prompt or voice: run the tests, then `nightly --script-only`, then look at stills of a real generated video at its cue moments and run `check_voice.py`.

## Adding things
- **New hook/meat/CTA:** append to `library_src/<product>.py` (IDs auto-continue: hook 51, meat M6, CTA C4), `library build`, `library lint`. Never edit `library/*.json` by hand. Update `TRIAL_SHAPES` in `tests/test_engine.py` when the counts change.
- **New product** (for example a peptide): `products.json`, `claims.json`, `library_src/<x>.py`, `common.PREFIX`, `library.PRODUCT_MODULE`, tests.
